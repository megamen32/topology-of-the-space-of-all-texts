Каждая панель получает собственные случайные метки и отдельную очередь. runner=experiments/evaluate_reference_readability.py


## Открытие страниц

В исследовании использовался образ `sha256:1200cb258799be285aca6f5f63c5f3fd4dc0145ca42b604502ceb2ec49c8aa9f`. Первые три реплики открывали по одной части очереди. Ещё две реплики получили пары 7 и 8 до первого обращения по этим адресам. Окончательное распределение записано в корпусе с каждой страницей.

Координатор закрепляет полный Docker image ID после технической сверки и выделяет реплики. Каждая обслуживает один вызов за раз. Параметр `--port` указывает опубликованный порт службы адресов этой реплики. `--node` принимает `local` или SSH-псевдоним. Для уже открытого координатором туннеля можно дополнительно передать `--local-port`. Номер части считается с единицы. По умолчанию рабочие файлы хранятся в личном каталоге состояния пользователя по соглашению XDG. Для другого каталога задайте `BABEL_STUDY_WORK` или передайте общую опцию `--work` перед именем команды.

```bash
python3 "$runner" pin-image "$verified_image_id"
python3 "$runner" generate --node "$node" --container "$replica" --port "$port" --shard 1/3
```

Остальные части передают другим выделенным репликам. Скрипт сверяет ID образа, привязку порта, сведения о весах и алфавите. Полные первичные ответы и метаданные попадают в `generated/`. Повторный запуск использует уже сохранённый текст. По завершении команда ниже закрепляет корпус, сохраняет точные UTF-8 байты страниц в `raw/` и готовит обе анонимные очереди в `packets/`.

```bash
python3 "$runner" pack
```

## Выдача читателям

Один файл из очереди — один новый сеанс. В файл входят нейтральная инструкция, схема ответа и три поля карточки — случайная метка, первая и вторая половины. При передаче вручную введите содержимое одного пакета в отдельный пустой сеанс с отключёнными инструментами, памятью и доступом к файлам. Сохраните исходный JSON ответа без редакторских исправлений. Исходный чат, каталог организатора и чужие ответы должны оставаться недоступны читателю.

Для автоматической выдачи нужен клиент OpenAI Python с поддержкой Responses API и настроенным подключением. Модели панелей фиксируют до первого чтения. Каждая команда делает по одному самостоятельному обращению на карточку. Панели можно запустить параллельно. В квитанции сохраняются фактическая модель, идентификатор ответа, отпечаток предъявленного пакета и исходный ответ.

```bash
python3 "$runner" pin-readers --a "$reader_a" --b "$reader_b"
python3 "$runner" read-panel a
python3 "$runner" read-panel b
```

Ответ отдельного внешнего сеанса можно принять той же формой.

```bash
python3 "$runner" record a "$card_id" --model "$reader_a" --session "$session_id" \
  --packet "$packet_file" --response "$response_file"
```

## Подсчёт

Когда собраны обе полные очереди, `reduce` проверяет цитаты и публикует эффект, интервалы, разногласия и контрольные результаты. При окончательном техническом пропуске организатор указывает причину через `--missing-reason` у `pack` или `reduce`. Такой исход расширяет диапазон возможных долей. Команда `verify` повторяет вычисления по опубликованным данным и сверяет текст отчёта.

```bash
python3 "$runner" reduce
python3 "$runner" verify
```
