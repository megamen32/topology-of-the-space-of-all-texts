# Можно ли отдать начало библиотеки языковой модели?

В первом слепом опыте Babel-1 связное высказывание получили 0 из 32 ранних и 0 из 32 глубоких фрагментов. У каталога есть 961 читаемая страница из готовых абзацев. Новый опыт проверяет, можно ли получать по ранним номерам разнообразные, заново сочинённые страницы и возвращать номер по произвольному тексту. [Опыт с Babel-1](babel1_readability.md)

## Как номер превращается в страницу

Порядок задаёт формула. Чтобы открыть № 17, достаточно вычислить страницу 17. Для примера возьмём восемь строк по три бита и договоримся переворачивать первый и последний бит номера. Тогда номер `001` открывает страницу `100`. Чтобы узнать номер этой страницы, переворачиваем те же биты и получаем `001`. Формула размещает все восемь страниц и делает доступной каждую по отдельности. В полном опыте таким же образом обращаются две поправки, которые вычисляет модель.

Записываем номер в виде 4096 цифр по основанию 256. Делим их на две равные части `L` и `R`. Функция `F(R)` по зерну сочиняет первую половину. Функция `G(U)` продолжает уже написанный текст. Каждая возвращает ровно 2048 индексов знаков исходного алфавита. Операция `^` означает побитовое исключающее ИЛИ между соответствующими индексами.

```text
unrank: U = L ^ F(R)      V = R ^ G(U)      страница = U || V
rank:   R = V ^ G(U)      L = U ^ F(R)      номер    = L || R
```

Повторное применение одной и той же маски возвращает исходные байты. Сначала восстанавливается `R`, затем `L`. Это доказывает взаимно однозначное соответствие для всех `2^32768` страниц даже при совпадающих ответах генератора. Нужно уметь повторить каждое предсказание в точности. Дискретные обратимые преобразования такого типа описаны в литературе. В прежнем плане Babel перестановка Фейстеля перемешивала номера внутри оболочки. Здесь предсказания меняют текст целой страницы. [Tran et al., Discrete Flows](https://arxiv.org/abs/1905.10347) · [Исходная программа Babel](../../ROADMAP.md)

При номере меньше `2^64` половина `L` нулевая. В `R` могут отличаться от нуля только последние восемь цифр. Значит, **первые 4088 знаков совпадают с текстом, который сочинил генератор для этого номера**. На номере ноль совпадают все 4096. Это даёт раннюю область без списка заготовок. У равномерно выбранного адреса по-прежнему равномерное распределение страниц, как у любой перестановки.

Хранить нужно только выбранный номер. Даже максимальный адрес целой страницы занимает 4096 байт. Для выбора одной из `2^2048` страниц достаточно номера из 256 байт. Перечисление всех этих страниц потребовало бы как минимум по одной операции на каждую. Здесь время открытия зависит от длины одной страницы и работы генератора. Исследовательский вопрос состоит в том, какую долю малых номеров сам генератор заполняет читаемыми текстами.

## Первая проверка с языковой моделью, 20 ноября 2026 года

На 44-м и 88-м серверах установлена одна сборка Qwen3:1.7b Q4_K_M размером 1,36 ГБ. Оба сервера открыли первые две страницы независимо. После перезапуска каждый получил файлы со второй машины и восстановил номера 0 и 1. Содержимое UTF-8 совпало побайтно. Все четыре половины заполнила модель. [Адаптер и параметры](../../experiments/ollama_generative_address.py) · [Карточка модели](https://huggingface.co/Qwen/Qwen3-1.7B)

| Номер | Полная страница | SHA-256 файла UTF-8 |

| 0 | [Рассказ на русском](qwen3_pages/0-ru.txt) | `9a99e387c77cde2b55d164f56f2976fc8ec3c189590d655bc662cdbcfdbc424e` |
| 1 | [Рассказ на английском](qwen3_pages/1-en.txt) | `54eef625ac7684346183d3cba4cc5a6fda7b5c3b4966fa82b91efce32ec911ee` |

В русском рассказе вторая половина дословно повторяет первые 103 знака первой. В английском примере последняя буква изменилась при внесении поправки для номера 1. Оба файла содержат ровно 4096 знаков. Сохраните файлы без завершающего перевода строки, если передаёте их команде `rank`.

На 88-м проверено и обратное направление на странице, заданной независимо от модели. Все 256 знаков исходного алфавита повторили в исходном порядке 16 раз. Команда `rank` вернула число из 9864 десятичных цифр. Вызов `unrank` восстановил все знаки. SHA-256 файла UTF-8 — `cebc32b8408756ca5ef7289727dedab241453eb6abdc3b66645a438516f2784c`.

**Куда попал Достоевский.** На 44-м взяли первые 4096 знаков «Белых ночей» из закреплённого корпуса. Их номер начинается с `642054563830…` и содержит 9864 цифры. Перед ним лежит около **45,36% всей библиотеки**. Затем сохранили первый и последний фрагменты, а остальные перемешали. Номер стал немного больше и начинается с `642054566138…`. Обе страницы по своим номерам восстановились побайтно. В этой паре оригинал оказался раньше перемешанного текста, но оба расположены далеко от начала. Частоту такого результата на разных произведениях предстоит измерить. [Источник страницы и смещение](../../experiments/evaluate_babel_1_shell.py)

Для воспроизведения возьмите `load_prose()[:4096]` из указанного модуля. Разделите строку выражением Python `re.split(r'(?<=[.!?])(?=\s)', page)`. Получится 44 части. Перемешайте внутренние 42 части командой `random.Random(20261120).shuffle(middle)` и склейте части без разделителя. SHA-256 исходного файла UTF-8 — `8078d1ab7c1d78649a0ec8f6eb6e6f3d70a233d13f862f3dd5d61301e8bbe427`, перемешанного — `445035ea0f0b6d95eb9075c80350fcc8d64ac588083840a8b19ced39f72d19d6`.

**Как повторить.** Издание закрепляет Ollama 0.32.1, манифест `8f68893c685c3ddff2aa3fffce2aa60a30bb2da65ca488b61fff134a4d1730e7`, слой GGUF `3d0b790534fe4b79525fc3692950408dca41171676ed7e21db57af5c65ef6ab6` и исходный алфавит Babel. В проверенном профиле на каждой машине стояла RTX 3080 Ti, использовались сборка CUDA 12, один слот, контекст 4096, пакет 128, значения KV в f16, отключённый Flash Attention и жадный выбор токенов. Адаптер проверяет версию службы и идентификаторы модели. Хеши выше позволяют проверить другую установку.

Каждый запрос к генератору начинает с пустого контекста выделенной службы. При коротком ответе адаптер запрашивает следующий фрагмент с учётом уже написанного. Если после восьми ответов половина всё ещё короче 2048 знаков, оставшиеся индексы вычисляются детерминированно с SHAKE-256. Поле `fallback_indices` показывает, сколько понадобилось таких знаков. В обеих опубликованных страницах это поле равно нулю для каждой половины.

Для отдельной службы Bash-команда ниже запускает Ollama в текущем терминале. Подставьте путь к установленной версии 0.32.1. Для выделенного каталога весов можно задать `OLLAMA_MODELS`. При доступе к реестру модель загружается командой `OLLAMA_HOST=127.0.0.1:18471 ollama pull qwen3:1.7b` из другого терминала. На проверенных серверах веса также доступны в штатной службе Ollama.

```bash
OLLAMA_HOST=127.0.0.1:18471 OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 \
OLLAMA_CONTEXT_LENGTH=4096 OLLAMA_FLASH_ATTENTION=false OLLAMA_KV_CACHE_TYPE=f16 \
OLLAMA_MULTIUSER_CACHE=false CUDA_VISIBLE_DEVICES=0 CUBLAS_WORKSPACE_CONFIG=:4096:8 \
OLLAMA_LLM_LIBRARY=cuda_v12 /path/to/ollama-0.32.1/bin/ollama serve
```

При работающей службе выполните в корне чистой копии проекта следующие команды.

```bash
run=$(mktemp -d)
cli=(python3 experiments/ollama_generative_address.py --endpoint http://127.0.0.1:18471)
for n in 0 1; do
  "${cli[@]}" unrank "$n" --out "$run/$n.txt"
  "${cli[@]}" rank "$run/$n.txt"
done
cmp "$run/0.txt" notes/experiments/qwen3_pages/0-ru.txt
cmp "$run/1.txt" notes/experiments/qwen3_pages/1-en.txt
```

## Следующий эксперимент и критерии решения

1. Шесть моделей уже прошли [сравнение на коротких русских и английских рассказах](small_models.md). Для выбранного издания зафиксировать выборку и правила оценки до генерации. Заранее включить генераторы студентов слов и абзацев в сравнение качества. Их seed задаёт выбор текста и не служит обратимым адресом.
2. **От номера к тексту.** Взять адреса 0–63 и по 64 номера из четырёх диапазонов с числом значащих битов 64, 8192, 16384 и 32768. Сопоставить с Babel-1 и raw на тех же номерах. В случайном порядке дать трём читателям полные страницы вместе с авторской прозой и контрольными страницами, у которых продолжения переставлены между разными началами. Для положительной оценки большинство должно суметь кратко пересказать одну мысль и указать, где во второй половине она продолжается. Отдельно считать почти дословные повторы между страницами. Предлагаемый порог для адресов 0–63 — преимущество минимум 20 процентных пунктов над Babel-1, нижняя граница 95%-го интервала парной разницы выше нуля. Доли по промежуточным глубинам покажут форму зависимости.
3. **От текста к номеру.** Взять отдельно 64 русские и 64 английские полные страницы, исключённые из настройки, из нескольких произведений. Для каждой переставить предложения с сохранением всех знаков и длины. Проверить, как часто оригиналу достаётся меньший номер. Считать победы по парам и интервал с группировкой по произведениям. Если интервал включает 50%, преимущество для чужой прозы остаётся открытым, даже если сгенерированное начало читается хорошо.

При провале прямой проверки сначала исследовать самого генератора, сравнив его текст со страницей на том же зерне. При провале обратной проверки измерить на тех же парах длину обратимого сжатия, учитывающего контекст. Короткое восстанавливаемое описание страницы даёт вторую гипотезу для назначения ей малого номера. Строгая сортировка по полной энергии прежней модели остаётся самостоятельной математической задачей.
