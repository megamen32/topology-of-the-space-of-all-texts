# Точный адрес страницы в издании Qwen

**У каждой из `2^32768` страниц есть ровно один адрес** при следующем условии. Каждый из двух предсказателей издания `babel-qwen3-ref-v1` на любом 2048-байтовом входе завершает вычисление и при повторе возвращает те же 2048 байт.

## Почему работают оба направления

В алфавите 256 различных кодовых точек. Страница из 4096 знаков задаётся их однобайтовыми индексами, поэтому страниц `256^4096 = 2^32768`. Номер от 0 до `2^32768 − 1` записываем в 4096 байтах, старшими вперёд, с ведущими нулями. Половины номера обозначим `L, R`, половины страницы — `U, V`. Функция `F(R)` сочиняет начало по зерну, `G(U)` продолжает заданное начало. Предсказатель может дать одинаковый ответ на разные входы. [Реализация rank и unrank](../../experiments/generative_coupling.py)

```text
unrank    U = L ⊕ F(R)      V = R ⊕ G(U)      вернуть U || V
rank      R = V ⊕ G(U)      L = U ⊕ F(R)      вернуть L || R
```

Здесь `⊕` — побитовый XOR, `||` — склейка. Дважды применённая маска снимает сама себя.

1. Начнём с **номера**. После открытия страницы `rank` получает `(R ⊕ G(U)) ⊕ G(U) = R`. С восстановленным зерном он получает `(L ⊕ F(R)) ⊕ F(R) = L`. Вернулся исходный номер.
2. Начнём с **чужой страницы**. После вычисления номера `unrank` получает `(U ⊕ F(R)) ⊕ F(R) = U`. С восстановленным началом он получает `(V ⊕ G(U)) ⊕ G(U) = V`. Вернулась исходная страница.

Для номера **меньше `2^64`** все байты `L` и первые 2040 байт `R` нулевые. Поэтому `U = F(R)`, а первые 2040 байт `V` совпадают с началом `G(U)`. Итого **4088 из 4096 знаков** совпадают с началом `F(R) || G(F(R))` для *этого* номера, включая возможное запасное заполнение. У нуля совпадают все знаки. У `2^64 − 1` меняются все последние восемь, так что общая граница точна. У двух соседних номеров зерно различается. Читаемость и сходство их страниц требуют наблюдений.

## Текст, короткий ответ и отказ службы

`rank` читает файл как строгий UTF-8 и принимает ровно 4096 кодовых точек алфавита. Начальный U+FEFF, пробел, LF и эмодзи 👍 занимают по одной позиции. Буква `é` занимает одну, последовательность `e` и U+0301 — две. Обе записи сохраняются буквально. В CRLF знак CR выходит за пределы алфавита. `unrank` переводит каждый индекс обратно в тот же знак. [Алфавит](../../models/top256_alphabet/alphabet_top256.json) · [Кодирование и декодирование](../../experiments/ollama_generative_address.py)

Сгенерированная проза проходит нормализацию и фильтр алфавита. При `stop=true` адаптер принимает остановку `eos`, `word` или `limit` и строку `content`. Ранний EOS с пустой строкой даёт ноль новых индексов. Для `F` предусмотрено до восьми запросов, для `G` — до четырёх сцен по три запроса. Продолжение может восстановить конец слова из исходной половины и добавить границу абзаца. Обе функции дополняют принятые индексы до 2048 байт выходом `SHAKE-256(b"tail\0" || ключ || принятые индексы)`. Ключ начала зависит от метки v2 и зерна `R`, ключ продолжения — от метки v3 и `U`. Это работает даже при двадцати успешно завершённых пустых ответах. [Предсказатели и заполнение](../../experiments/qwen_reference.py) · [Правила сцен](../../experiments/ollama_continuation_v3.py)

Тайм-аут, HTTP-ошибка вычислителя, незавершённый ответ и явное `truncated=true` прерывают операцию. Для этих случаев служба возвращает 503 без страницы или номера. Недопустимый текст или номер даёт 400, тело запроса свыше 65 536 байт — 413. Для любой допустимой страницы телу запроса штатного клиента хватает 16 395 байт. При отказе CLI завершается с кодом 1. Кеш Python хранит только успешно вычисленные половины, до 32 каждого вида. [Обработка запросов и ошибок](../../experiments/qwen_reference.py)

## Сколько токенов помещается при любом входе

В закреплённом GGUF у байтового токенизатора `gpt2/qwen2` есть токен для каждого из 256 байтов. Слияния BPE могут только уменьшить их число, автоматический BOS выключен. В контекст входит готовая строка `prompt` для `/completion`. JSON-схема задаёт грамматику ответа. Переменные отрывки и поля обрезаются **после** экранирования по байтам UTF-8 с отбрасыванием неполных кодовых точек на краях. В последнем столбце учтены весь ответ и запас в восемь токенов. [Рамка начала](../../experiments/ollama_generative_address.py) · [Рамки продолжения](../../experiments/ollama_continuation_v3.py)

| Стадия | Верхняя граница входа, байт UTF-8 | Ответ, токенов | Всего из 6144, не более |
| --- | ---: | ---: | ---: |
| Начало | 3064 = 4096 − 1024 − 8 | 1024 | 4096 |
| Чтение сцены | 440 рамки + 1360 начала + 7 пропуска + 2720 конца = 4527 | 224 | 4759 |
| План | 665 рамки с самой длинной инструкцией + 4 поля × 256 = 1689 | 240 | 1937 |
| Проза | 650 русской рамки + 5 полей × 256 + 210 конца фразы + 2 перевода строки = 2142 | 1024 | 3174 |

У начала без отрывка запрос занимает до 707 байт. Английская рамка прозы короче русской. Оценки охватывают и 2048 четырёхбайтовых эмодзи, и строку из одних `&`.

## Как проверить свой файл

Команда `./deploy/qwen-reference/build.sh` закрепляет веса Qwen3-1.7B Q4_K_M, алфавит, код, llama.cpp b9888 и CPU-библиотеку Haswell для Linux x86-64. В образе один слот на 6144 токена, четыре вычислительных потока, batch и ubatch по 128. Каждый запрос задаёт `cache_prompt=false`, слот 0, seed 0, температуру 0 и top_k 1. Сервер также запускается с `--no-cache-prompt`. ID обоих образов сверьте командой `docker image inspect --format '{{.Id}}' babel-qwen-reference:v1`. [Сборка с SHA-256](../../deploy/qwen-reference/build.sh) · [Параметры сервера](../../deploy/qwen-reference/Dockerfile) · [ID образа опыта](reference_readability/runtime.json)

Возьмите независимо подготовленный файл. Штатный порт службы адресации — 18862 снаружи, 8081 внутри контейнера. Задайте в Bash переменную `peer` с URL второго экземпляра того же образа с пустым кешем и выполните из корня проекта. [Запуск экземпляра](../../deploy/qwen-reference/README.md) · [Команды CLI](../../experiments/qwen_reference.py)

```bash
(
  set -eu
  src=/путь/к/странице.txt
  work=$(mktemp -d)
  cli=(python3 -B experiments/qwen_reference.py)
  encoder=http://127.0.0.1:18862
  "${cli[@]}" health --endpoint "$encoder"
  "${cli[@]}" health --endpoint "$peer"
  n=$("${cli[@]}" rank --endpoint "$encoder" "$src")
  "${cli[@]}" unrank --endpoint "$peer" "$n" --out "$work/copy.txt"
  cmp -- "$src" "$work/copy.txt"
)
```

`rank` печатает точный десятичный номер, `unrank` записывает UTF-8 и печатает SHA-256. Код 0 у `cmp` означает побайтовое совпадение с исходником. Для проверки в другом направлении начинают с выбранного номера и восстанавливают его через `rank` во втором процессе.

## Проверенные факты и открытые вопросы

- Локально прошли `python3 -B experiments/generative_coupling.py` и `python3 -B -m unittest experiments.test_qwen_reference`. В первом тесте перебраны обе композиции для 65 536 двузначных страниц. На полной длине проверены граничные номера, произвольные страницы и префиксы. Во втором использован подставной вычислитель. Отдельно сверены все 256 пар «индекс — знак», пустой EOS и ошибки обработчиков без сокетов. [Тесты адаптера](../../experiments/test_qwen_reference.py)
- Образ содержит проверенные по SHA-256 веса, восемь файлов вычислителя, алфавит и код издания. Один архив перенесён на обе машины. При полной сборке без кеша содержимое файлов совпало, а Docker присвоил другой ID из-за меток времени каталогов слоя. При проверке после перезапуска совпали 12 выходных токенов, во всех шести коротких запросах `cache_n=0`. [Сборка и сверка архива](../../deploy/qwen-reference/README.md)
- Сервер 88 открыл № 41, сервер 100 получил тот же номер по всем 4096 знакам. Для обратного опыта вход составили вручную из исходного алфавита, повторённого 16 раз. Сервер 100 вычислил адрес длиной 32 767 бит, сервер 88 восстановил исходный UTF-8 побайтно. В квитанции сохранены сама страница № 41, точный шестнадцатеричный адрес второго входа, времена и контрольные суммы. [Результаты обеих проверок](qwen_reference_verification.json)
- Служба рассчитана на закреплённый нативный вычислитель. Для проверки целостности файлов образа выполните `docker exec babel-qwen-reference-v1 sha256sum --check --strict SHA256SUMS`. Сам маршрут `/health` сообщает ожидаемый хеш весов и проверяет число слотов и размер контекста. При подмене вычислителя испорченный ответ может получить ошибочный HTTP-статус: например, глубоко вложенный JSON приводит к 400, а отсутствие поля `truncated` адаптер принимает за обычное завершение. [Код адаптера](../../experiments/qwen_reference.py)
- Для всех входов остаются открытыми тотальность и побайтовая повторяемость самого вычислителя Qwen. Граница проверки — указанные артефакты и backend x86-64/Haswell. Читаемость на ранних и далёких адресах измеряется слепым сравнением. [Протокол оценки текстов этого издания](reference_readability/protocol.json)
