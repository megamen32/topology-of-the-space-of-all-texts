# План реализации и проверок библиотеки

Основная читалка открывает обычные адреса, конечный каталог и номера Babel-1. После слепой проверки фрагментов следующий опыт посвящён генерации целых страниц и адресам независимой прозы. [Прототип и критерии решения](../experiments/generative_coupling.md) · [Текущий план](roadmap.md) · [Научный ROADMAP](../../ROADMAP.md)

## Работающая реализация

- `site/library.html` и `site/assets/library.js` — поиск по тексту, открытие адреса и навигация.
- `experiments/backend_app.py` — API адресации и оценки стоимости текста.
- `experiments/babel_shell_v1.py` — нумерация по бинарным оболочкам.
- `experiments/hierarchical_enumerator_v1.py` — каталог абзацев и обмен страницами в исходном алфавите.
- `deploy/babel-walk.service` — служба публичной читалки.

# Этап 0. Проверки готовой библиотеки

### 0.1. Технический аудит reader-а

Проверить существующий `library.html` и `library.js`:

- нулевой адрес;
- максимальный адрес;
- page64 ↔ decimal;
- `rank(unrank(n))`;
- `unrank(rank(text))`;
- переходы page64;
- random page;
- копирование адреса;
- мобильный layout.

### 0.2. Канонический API-контракт

Описать как текущую основу:

```text
raw rank:   нормализованный текст → число
raw unrank: число → 4096-символьная страница
```

Сохранить действующие URL и page64-адреса. Смысловой слой не должен ломать старые deep links.

### 0.3. Основной вход

Читалка расположена на `all.bezrabotnyi.com`. Домен `babel.bezrabotnyi.com` перенаправляет на него с кодом 308. [Открыть библиотеку](https://all.bezrabotnyi.com/library.html)

# Этап 1. Интерфейс читалки

В читалке есть отдельные действия для поиска обычного адреса, открытия страницы каталога и перехода по номеру Babel-1. При изменении интерфейса проверять подписи режима и кнопок перехода. При копировании адреса важно сохранить режим. Обычный поиск использует нормализованный алфавит, каталог и модель Babel-1 — исходный.

Для обычного адреса сохранить показ `page64` и полной десятичной записи. В исходном макете также предусмотрена ссылка для повторного открытия страницы. У Atlas отдельный литературный режим. У цитат читательского маршрута указаны авторы.

# Этап 2. Короткий кластерный опыт

В этом опыте страницы длиной до 256 знаков упорядочены по сумме стоимостей кластерных переходов. При равенстве стоимости действует точный порядок по алфавиту. Для проверки адреса открыть по номеру ту же страницу и восстановить её номер.

В первоначальном плане предложены пять контрольных примеров.

1. связная русская фраза;
2. связная английская фраза;
3. та же фраза с опечаткой;
4. повтор одного символа;
5. случайный шум.

Для примера указывать текст, его обычный адрес и поддерживаемую длину. При доступном кластерном расчёте показывать номер, общую стоимость и среднюю стоимость знака. У бинарной оболочки Babel-1 своя стоимость — число выходов за первые 16 вариантов. В первом слепом опыте связность оценивали по фрагментам длиной 240 знаков.

# Этап 3. Глобальный порядок по стоимости исходной модели

Цель исследования — вычислять точный номер 4096-символьной страницы в порядке суммарной стоимости модели по всей странице и восстанавливать страницу по этому номеру. Читалка, каталог и бинарные оболочки уже работают независимо от этой задачи.

## Задачи

### 3.1. Эталонный direct-DP

Для длин 8, 16, 32 и 64 построить медленный, очевидный счётчик energy buckets.

Он нужен не для production, а как oracle для проверки оптимизаций.

### 3.2. Состояние границы блока

Определить, что передаётся между блоками:

- состояние конечной модели;
- накопленная стоимость;
- число продолжений;
- точный формат таблицы перехода.

### 3.3. Chunked counting

Считать полную страницу блоками, сохраняя состояние на границах. Простое перемножение независимых блоков запрещено: оно теряет переходы между блоками.

### 3.4. Сверка оптимизации с oracle

Для каждой длины требовать:

```text
chunked_count == direct_count
```

### 3.5. Глобальный смысловой rank

После histogram по общей стоимости реализовать:

```text
номер = количество страниц с меньшей стоимостью
      + точное смещение внутри равной стоимости
```

### 3.6. Глобальный смысловой unrank

По номеру:

1. выбрать bucket стоимости;
2. выбрать путь по состояниям;
3. выбрать каждый следующий символ;
4. восстановить всю страницу.

### 3.7. Доказательства

Проверить:

- покрытие всего raw-пространства;
- отсутствие повторов;
- `rank(unrank(n)) = n`;
- `unrank(rank(page)) = page`;
- монотонность по стоимости;
- корректность переходов между блоками.

**Параллельно:** 3.1 и 3.2 стартуют одновременно; 3.3 зависит от обоих; 3.4 можно вести рядом с 3.3; 3.5 и 3.6 начинаются после устойчивого счётчика; 3.7 идёт с самого начала как набор admission-тестов.

Этап завершится, когда для полной длины будут проверены обратимость и порядок по общей стоимости.

# Этап 4. Проверка публичной читалки

Канонический адрес выбран, HTTPS и перенаправление настроены. При проверке публичной версии открыть читалку, проверить обычный адрес и навигацию. В каталоге проверить № 0, № 1 и первый номер за каталогом (сейчас № 961). В Babel-1 открыть номер и по полученной странице восстановить тот же номер. [Публичная читалка](https://all.bezrabotnyi.com/library.html)
