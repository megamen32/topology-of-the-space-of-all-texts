# План реализации и проверок библиотеки

## Сравнение генераторов

1. Для сравнения с LLM взять как минимум две конфигурации student-моделей — [paragraph 0.85/64 и word 0.55](status.md#что-удавалось-ранним-моделям). Температура и ветвление относятся к исследовательским конфигурациям. В публичной форме генератора пользователь задаёт Seed, Length и Mode.
2. Подготовить полные страницы. Для student записать конфигурацию, seed, запрошенную и полученную длину. Для LLM взять параметры и результаты межсерверной сверки из [протокола полностраничного опыта](../experiments/generative_coupling.md).
3. Дать читателям тексты без названия генератора, номера и оценки Score. При попарном сравнении уравновесить расположение образцов слева и справа. Отдельно посчитать предпочтения читателей и выбор стороны.
4. Для проверки адресов взять независимую прозу и версии тех же текстов с переставленными предложениями. В каждой паре использовать один порядок и проверить восстановление страницы по номеру. Критерии сравнения заданы в [протоколе эксперимента](../experiments/generative_coupling.md).

## Как повторить проверку сайта

- Выполнить GET для корня, генераторов и читалки на обоих доменах. Сверить конечные заголовки и пройти по видимым ссылкам с главной к генераторам и оттуда в читалку. [Карта сайта](../../README.md#карта-сайта)
- В генераторе повторить выбор с одним seed, изменить seed, затем набрать свой текст и нажать Score generated. [Контрольные значения для шести режимов](../../site/README.md#шесть-режимов-генератора)
- В Search проверить преобразование «текст → номер → страница» для raw и короткого кластера. Для блочной композиции открыть номер и восстановить его по полной странице. В читалке проверить границу каталога и обе стороны адресации Babel-1. [Результаты публичной проверки](status.md#что-проверено-на-публичном-сайте)
- При изменении обычной адресации дополнительно проверять граничные номера, преобразование `page64` в десятичную запись и обратно, переходы читалки, копирование адреса и отображение на телефоне. [Запуск и проверки из чистой копии](../../README.md#локальный-запуск)

## Исследование полного порядка по стоимости

В коротком кластерном опыте есть прямой счётчик и сверка блочного подсчёта с ним. Метод `verify_against_raw_dp` сравнивает число страниц для каждого значения стоимости и проверяет покрытие пространства. [Счётчик и сверка](../../experiments/cluster_chunk_counting.py)

Для полного контекстного порядка предстоит масштабировать подсчёт с передачей состояния между блоками. По числу страниц меньшей стоимости и смещению внутри равной стоимости можно вычислять номер. Для обратного хода нужны числа продолжений при каждом возможном следующем знаке. Критерии завершения и проверки на малых пространствах собраны в [открытых задачах](open_problems.md#4-проверки-нового-порядка).
