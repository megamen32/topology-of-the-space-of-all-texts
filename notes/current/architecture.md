# Текущая архитектура

Главная отправляет текст или номер в API. Генераторы строят образцы в браузере. В поиске и читалке место вычисления зависит от выбранного порядка. Flask отдаёт HTML, JavaScript и обрабатывает `POST /api/rank` и `POST /api/unrank`. [Карта сайта](../../README.md#карта-сайта) · [Обработчики API](../../experiments/backend_app.py)

## Генерация по seed

JavaScript загружает таблицы student-моделей. Строка Seed задаёт начальное состояние генератора псевдослучайных чисел, Mode определяет правила выбора текста. Режим paragraph/hierarchical строит абзац из шаблонов предложений. Общая функция `scoreText` вычисляет стоимость текущего текста в поле. Чтобы получить номер этого текста, пользователь выбирает порядок адресации в Search. [Шесть режимов, Score и примеры](../../site/README.md#шесть-режимов-генератора)

## Обычный адрес

Страница raw содержит 4096 позиций в нормализованном алфавите из 256 знаков. Индексы знаков образуют цифры числа в системе с основанием 256. Все `256^4096 = 2^32768` страниц имеют точный адрес. В Search и читалке обычный номер вычисляется в браузере. На главной те же операции выполняются через API. [Операции в браузере](../../site/assets/shared.js) · [Обращения с главной](../../site/assets/address-space.js)

## Кластерные блоки

В режиме **Cluster energy exact** (`exact_cluster_mvp`) сервер считает число продолжений с заданной суммой стоимостей переходов между кластерами. `RawClusterRanker` упорядочивает все страницы выбранной длины от 1 до 256 знаков по этой сумме. При равенстве стоимостей решает порядок знаков в алфавите.

В режиме **Hierarchical exact** (`exact_hierarchical_v1`) `HierarchicalRawRanker` присваивает каждому блоку из 256 знаков свой точный кластерный номер. Полная страница состоит из **16 × 256 = 4096 знаков**. Их номера составляют один адрес в порядке следования блоков, и по этому адресу восстанавливаются все 4096 знаков. Глобальный порядок по сумме контекстных стоимостей через границы блоков остаётся открытой задачей. [Реализация обоих порядков](../../experiments/cluster_counting_mvp.py) · [Подсчёт с передачей состояния](../../experiments/cluster_chunk_counting.py)

## Каталог и оболочки Babel-1

В читалке **«Читаемое начало»** (`hierarchical_catalogue_v1`) ставит 961 пару из готовых абзацев на первые номера. Обмены с прежними страницами сохраняют биекцию во всём исходном алфавите. Это отдельный порядок адресации. [Реализация каталога](../../experiments/hierarchical_enumerator_v1.py)

В **Babel-1** (`babel_1_shell`) Markov-5 упорядочивает варианты следующего знака. Номер задают энергетическая оболочка и место внутри неё. Энергия равна числу выходов за первые 16 вариантов. Для экспериментов ранжировщику можно передать словесную перестановку **WordV1** (`ContextPermutationWordV1`), которая отдаёт приоритет вероятным продолжениям слов, а остальные знаки упорядочивает по Markov-5. По умолчанию публичный ранжировщик использует Markov-5. [Реализация перестановок и оболочек](../../experiments/babel_shell_v1.py)

## Эксперимент с языковой моделью

В исследовательском прототипе предсказания LLM входят в обратимое преобразование двух половин страницы. Воспроизводимость между серверами и связность таких страниц проверяются в отдельном опыте. [Конструкция и результаты полностраничной сверки](../experiments/generative_coupling.md)
