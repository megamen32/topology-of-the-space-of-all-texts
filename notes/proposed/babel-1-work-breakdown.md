# Babel-1: инженерная декомпозиция после научного решения

Этот план начинает реализацию только после принятия S0–S3 из
`babel-1-scientific-program.md`. Он не заменяет существующий raw-reader.

## Критический путь

```text
спецификация версии → латентный exact core → test vectors → API → reader → canary
                 └────────────────────────→ эксперимент качества ──────────┘
```

## E0. Контракт версии (один короткий результат)

- Зафиксировать `babel-1.json`: алфавит, длину, функции нормализации, описание
  `M`, целочисленные `c`, tie-break, алгоритм перестановки внутри оболочки.
- Добавить хеш контракта в каждый ответ API.
- Создать независимые векторы `text / latent / babel_1_rank / raw_rank`.

Готово, когда два минимальных референса читают один JSON и совпадают на
векторах. Параллельно с E1 можно собрать тестовый набор, но не его ожидаемые
адреса.

## E1. Латентный exact core

Проверить и довести до контрактного ядра уже существующий эксперимент
`experiments/babel_shell_v1.py` (`BinaryShellRanker`, `ContextPermutationV1`,
`BabelRanker4096`); выделять новый модуль стоит только после того, как это
уменьшает, а не дублирует код:

- `latent_rank(z)`, `latent_unrank(rank)`;
- `encode_latent(z) -> page`, `decode_page(page) -> z`;
- `rank_page`, `unrank_page` как композиции;
- доступ к точному размеру каждой оболочки и диагностике.

Не встраивать эту логику в `RawClusterRanker`: у него другая семантика —
подсчёт энергии текущего student-а. Переиспользовать его тестовые паттерны и
big-int утилиты разрешено.

Готово, когда доступны 4096-символьные round-trip и сумма оболочек равна
`256^4096`.

## E2. Детерминированная контекстная перестановка

Новый адаптер, например `experiments/babel_1_permutation.py`:

- по префиксу получает ровно 256 упорядоченных кандидатов;
- детерминированно разбирает равенства;
- проверяет, что результат — перестановка алфавита;
- квантует/привязывает модель строго в соответствии с E0.

Можно использовать `models/student_fsm_v1/student_fsm_v1.json` как первую
модель, если он выдаёт полный порядок всех байтов. Если нет — нужен явный
fallback-order, включённый в хеш версии.

Готово, когда обратимость работает на произвольных страницах и нет зависимостей
от float/локали/версии runtime.

## E3. Независимая проверка и property tests

- exhaustive enumerate при уменьшенных `|Σ|, N`;
- случайные 4096-страничные round-trip;
- проверка границ: `0`, `space−1`, начало/конец оболочек;
- воспроизводимость на двух интерпретаторах;
- фиксированные негативные примеры невалидного алфавита/длины.

Зависит от E1 и E2; реализация тестового каркаса может идти параллельно.

## E4. Эксперимент качества

- Зафиксировать эталонные русские, английские, смешанные и шумовые строки.
- Генерировать срезы адресов: ранние оболочки, средние квантили, хвост.
- Сравнить с raw base-256 и текущим `HierarchicalRawRanker`.
- Публиковать метрики, seed, версию модели и неудачные образцы.

Это независимая от API задача после E1/E2. Она решает, годится ли модель, но
не определяет математическую корректность адресации.

## E5. API

Расширить `experiments/backend_app.py`, не меняя raw-маршруты:

- `POST /api/babel-1/rank`;
- `POST /api/babel-1/unrank`;
- `POST /api/babel-1/explain` — только диагностические стоимость/версия, не
  «доказательство смысла»;
- явные поля `order: babel-1`, `coverage: full`, `language_quality: measured`.

Готово, когда запросы содержат E0 hash, ошибки валидации ясны, API проходит
E3-векторы.

## E6. Reader и язык интерфейса

Изменить `site/library.html` и `site/assets/library.js` малыми шагами:

- русские подписи для уже готовой raw-библиотеки;
- две разные операции: «Найти обычный адрес» и «Открыть адрес Babel-1»;
- рядом с Babel-1 — версия и короткое честное объяснение;
- Atlas вынести в «литературный режим», не в основной путь.

Интерфейс зависит от E5. Русификацию raw-reader можно выпускать отдельно.

## E7. Production и canary

- направить `babel.bezrabotnyi.com` на существующий Babel upstream без login;
- проверить raw-reader, Babel-1 rank/unrank, назад/вперёд, мобильный экран;
- сравнить production-ответы с E3-векторами;
- оставить `all.bezrabotnyi.com/library.html` безопасным адресом.

## Что можно делать параллельно

| Поток | Можно начать | Блокер |
|---|---|---|
| E1 проверка существующего exact latent core | после E0 | принятая `c` и tie-break |
| E2 permutation adapter | после E0 | принятая модель `M` |
| E3 test harness | сразу | ожидаемые векторы из E1/E2 |
| E4 evaluation harness | сразу | результаты E1/E2 |
| русификация raw-reader | сразу | нет |
| nginx/DNS аудит | сразу | доступ к production-хосту |
| E5 API | E1+E2+E3 | стабильный core |
| E6 semantic UI | E5 | стабильный API |
| E7 canary | E5+E6 | production route |
